AutoCAD LISP Routines

Every LISP routine currently in the team's shared LISP library, what command each one registers, and what it actually does. Source files live on the shared drive — this page is the reference for what's available and how to run it.

Source folder: Peake Design - Documents\TECHNICAL RESOURCES\AUTOCAD\LISP ROUTINES
How to Load a Routine
  1. In AutoCAD, type APPLOAD (or drag the .lsp file straight onto the drawing window).
  2. Browse to the LISP ROUTINES folder above and select the file(s) you need, then click Load.
  3. Type the command name shown below (not the filename) to run it. A file can define more than one command — load once, use any of them.
  4. Loaded routines only last for the current AutoCAD session. To have a routine load automatically every session, add it to the Startup Suite in APPLOAD.
Text Extraction
Pulls the string content out of TEXT/MTEXT objects so it can be pasted elsewhere without retyping it.
ExtractText.lsp TXTTOCLIP ALLTXTTOCLIP TXTTOCLIP2
Select text objects in the order you want them read, and the concatenated string is copied to the Windows clipboard. TXTTOCLIP selects TEXT objects only; ALLTXTTOCLIP also accepts MTEXT; TXTTOCLIP2 is an alternate implementation that writes to a temp file and pipes it through clip.exe instead of the ActiveX clipboard method — useful as a fallback if the primary method misbehaves.
Hatch Tools
Clear Hatches - V2.lsp BLOCKHATCH
Explodes the selected hatch(es) and deletes the resulting boundary geometry, leaving only hatches that already existed elsewhere in the drawing untouched. Useful for stripping hatch patterns out of an import without hand-picking every boundary line.
Block & Layer Tools
Set Block Layer - Prompted.lsp PROMPTEDBLOCK
Prompts for a layer name, then a block to select. Every object inside that block definition is reassigned: objects already on layer DRAFT stay on DRAFT, everything else moves to the layer you typed; linetype is set to DASHED2 or CONTINUOUS the same way. Depends on the helper routine below, which must be loaded alongside it.
Apply to Block - Sub.lsp
Not a standalone command — a Lee Mac utility function (LM:ApplytoBlockObjects) that runs a supplied function against every object inside a block definition. Load it whenever another routine (such as PROMPTEDBLOCK above) calls it.
Dependency, not a command
Import Tools
PDFImport.lsp PDFBATCHIMPORT
Prompts for a PDF, then a base point, and imports every page of that PDF as vector geometry, stacking each page 1'-0" below the last starting from the base point. Saves importing a multi-page PDF one page at a time.
PDG - Import Revit DWGs into DWG.lsp
Runs automatically the moment it's loaded — there is no command to type. It opens a folder browser, then for every Revit-exported .dwg in that folder it xrefs the sheet into the current drawing, draws a green page-boundary rectangle around it, labels it with the sheet name, and lays sheets out left-to-right/top-to-bottom by sheet number, before binding all the xrefs. Written to assemble a single DWG containing every sheet/view from a Revit export. Boxes sometimes need manual resizing or repositioning afterward — it makes layout assumptions that don't always hold.
Runs on load — no command name
Revit Interop
PDG - Railing Csv Export.lsp PDGRAILCSV
Select LINE and ARC entities representing railing runs, and it writes one CSV row per entity (Type,ID,X1,Y1,X2,Y2 for lines, plus a third on-arc point for arcs) for the Revit-side importer RailingTools.Commands.CreateRailingsFromCsvCmd in PDGRevitAddinCollection. Reads the drawing's INSUNITS to convert to decimal feet automatically (and asks you to confirm the unit if the drawing doesn't have one set); read-only against the drawing. Polylines are out of scope and are reported as skipped rather than silently dropped or auto-exploded.
This is the v2 CSV contract (one row per run, with a leading Type column) — a breaking change from an earlier two-row-per-run format. The Revit-side parser must match this contract or the file won't import correctly.
Brighton Project — Layer Workflow
A three-step layer workflow built for one specific project's demo/remain marking process, not a general-purpose tool.
Brighton_Create_Layers.lsp CREATEBPLAYERS
Step 1. Creates the two layers the rest of the workflow needs: To_Demo (red) and To_Remain (green).
Brighton_Assign_Layers.lsp ASSIGNBPLAYERS TODEMO TOREMAIN
Step 2. ASSIGNBPLAYERS selects objects then prompts Demo/Remain to choose the target layer; TODEMO and TOREMAIN are one-step shortcuts that skip the prompt. All three require To_Demo/To_Remain to already exist (run CREATEBPLAYERS first).
Brighton_Delete_Layers.lsp CLEANUPLAYERS CUSTOMCLEANUPLAYERS
Step 3. CLEANUPLAYERS deletes every object on a hard-coded list of project layers (the original architectural layers now superseded by To_Demo/To_Remain) and then deletes the layers themselves, after a Yes/No confirmation prompt. CUSTOMCLEANUPLAYERS does the same thing but for layer names you type in one at a time instead of the hard-coded list.
Destructive — deletes objects permanently
Brighton_Save_Files.txt
A .txt copy of Brighton_Delete_Layers.lsp's code, not a distinct routine. Rename it to .lsp if it ever needs to be loaded directly — otherwise treat it as a backup of the file above.
Duplicate of Delete_Layers, not loadable as-is
