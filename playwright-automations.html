Playwright Automations

Every task script in pdg-playwright-automation — what it automates, what triggers it, and what it reads or writes. These scripts drive real browser sessions against Monograph, Matterport, Airtable, Autodesk ACC, and the City of Calgary's website because none of those expose a usable API for the workflow in question.

Source folder: Peake Design - Documents\Technical Resources\playwright — full technical reference in that folder's DOCUMENTATION.md and CLAUDE.md.
How to Run a Task
  1. Open a terminal in the playwright folder above.
  2. Run it via its npm shortcut, e.g. npm run task:sync-budget-hours, or directly: node task-<name>/run.js '<json-payload>'.
  3. Most tasks log a numbered step trail to the console and write debug screenshots to ./session/ — check there first if a run fails.
  4. Six tasks (marked webhook below) are also wired into server.js and can be triggered by POSTing to their route once npm run server is running. Everything else is CLI-only.
Monograph — Project Setup
Monograph has no public API. These fill in its project-management screens directly from Airtable, using the same React-Select and popup-dismissal patterns throughout.
task-create-monograph-project/run.js webhook
Creates a new Monograph project from an Airtable T01_Job_List record — template, name, number, client, category, start date, service fee (75% of rough fee estimate), and consultants (Matterport, Ben Pond Architect where applicable) — then writes the resulting project URL back to Airtable.
task-add-monograph-client/run.js webhook
Creates a new client entry in Monograph's directory from an Airtable T05_Clients record (company name, primary contact, email, phone). Read-only against Airtable — no writeback.
task-add-monograph-consultant/run.js webhook
Creates a new consultant company in Monograph's directory from an Airtable T04_Vendors record, including discipline (a React-Select variant with its own CSS classes). Read-only against Airtable.
task-get-monograph-url/run.js webhook
Looks up an existing Monograph project by job number and writes its URL back to Airtable — for projects created before the URL was being recorded. Writes the literal string "NOT FOUND" on failure so the Airtable record shows a clear error state.
Monograph — Budget & Hours
Reconciling planned vs. logged hours in Monograph's Performance and Planner tabs, which expose no export or API for this data.
task-sync-monograph-performance/run.js webhook queued
Scrapes each project's fee-spent-to-date (billable and total) from the Performance tab and writes both to Airtable. The Performance table has no stable selectors, so it scrapes by matching month-label text and walking up to the row container. The only server route that runs single-file (FIFO queued) rather than in parallel.
task-sync-budget-hours/run.js
Sums every phase's "Total" hours row in a project's Planner and writes the total to the linked Airtable proposal's Hours Allowed field, for proposals that don't have it set yet. Batch mode processes every blank proposal; a job number argument runs one project only.
task-budget-align-hours/run.js
For one project, reconciles each team member's assigned budget hours to their actually-logged hours. Monograph exposes logged hours only inside the delete-role confirmation modal, so the script opens that modal to read the number and always cancels — it never confirms a delete. Then copies each phase's updated total into the phase budget field. Requires a job number or full project URL as its argument.
Opens a delete-confirmation modal (always cancelled) to read data
task-update-project-colors/run.js
Sets every active project's Monograph color swatch to match its Airtable Sub Type, via a hardcoded 32-entry name-to-color-slot map. Skips the internal templates job and any Sub Type not in the map.
task-ben-pond-hours/run.js
Weekly sync of one consultant's (Ben Pond Architect) Monograph timesheet hours into a separate "Syllabus" Airtable base that tracks his hours per project. Runs automatically every week via scheduled-run.ps1 in Windows Task Scheduler; supports --dry-run.
Matterport
task-matterport-sync/run.js webhook
Opens a Matterport model, enables public link sharing, and writes the share URL, scan date, and embed code to the Matterport-specific Airtable base (a different base from every other task here). Notes are appended, not overwritten.
Calgary Due Diligence Pipeline
Four scripts run in sequence to build the interactive zoning/business due-diligence tool already published on this site as Calgary Business Tenancy Checker. Run in this order: business matrix → land-use matrix → combined matrix → due-diligence HTML.
task-calgary-business-matrix/run.js
Drives Calgary's "Start a Business" application wizard for every business activity in the city's system, harvesting the full licensing question tree for each one. Resumable — a killed run picks up where it left off from a progress checkpoint file.
task-calgary-land-use-matrix/run.js
Scrapes the full text of Calgary's Land Use Bylaw 1P2007 across ~56 zone-district pages to build the canonical use list and a zone × use permitted/discretionary matrix. No login required; supports --resume.
task-calgary-combined-matrix/run.js build-html.js
Pure data processing, no browser: cross-references business activities against zoning permissions to produce a reviewable Excel workbook (run.js), then build-html.js bakes the result into the self-contained interactive HTML tool. Matching quality depends on three hand-maintained lookup tables mapping business categories and ambiguous terms (e.g. "Airbnb", "Gym") to bylaw use groups.
Matching accuracy depends on manually maintained lookup tables
task-calgary-carl-pdfs/run.js
Scrapes Calgary's CARL permit-application-requirements page for every linked PDF/XLSX, downloads them, and builds an Excel index classified by permit type (DP/BP) and category (Residential/Commercial).
Airtable & Autodesk ACC
task-document-airtable-automations/run.js
Walks every "Live" automation listed in a tracker base, opens each one in Airtable's Automations editor, screenshots it, and reads out its trigger/action configuration — including pulling the full script text out of "Run a script" steps. Compiles everything into one Markdown reference doc and pushes it to GitHub if configured. This is the tool that produced the automation screenshots already in this project's session/ folder.
No stable selectors — scrapes by card geometry and text heuristics
task-create-forma-collection/run.js
Creates a new Content Collection in Autodesk ACC's design-management admin panel for the Peake Design Group hub, optionally adding user groups with read/download/upload/edit permissions.
task-upload-content-catalog/run.js
Bulk-uploads local Revit family (.rfa) files into Autodesk Content Catalog in batches of 25, assigning each top-level local folder to a same-named ACC collection. Supports resuming a specific folder from a given file index, and a --dry-run listing mode.
